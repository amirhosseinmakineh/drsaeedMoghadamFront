## تغییر رفتار فرم موجود

همان فرم `consult-lead__form` در Home نگه داشته شده و فقط دو ورودی فارسی نام و نام خانوادگی و موبایل دارد. انتخاب خدمت، توضیحات و موفقیت نمایشی قبلی حذف شده‌اند. فرم جدید یا منطق تخصیص جدید ساخته نشده است.

از `HttpClient` موجود و `environment.apiBaseUrl` استفاده می‌شود:

```http
POST /api/consultation-requests
```

```json
{"fullName":"علی رضایی","phoneNumber":"09123456789","requestId":"frontend-generated UUID"}
```

`requestId` فقط هنگام ارسال معتبر در مرورگر ساخته می‌شود و در UI دیده نمی‌شود. هیچ `serviceId`، `notes`، آیدی مشاور یا تاریخ ساختگی ارسال نمی‌شود. در شبکه نامطمئن، Timeout، پاسخ خطا یا پاسخ بدون تأیید، اطلاعات و شناسه همان درخواست حفظ می‌شوند؛ تغییر محتوای نرمال‌شده شناسه جدید می‌سازد. تغییر صرفاً ظاهری شماره به ارقام انگلیسی یا پیش‌شماره معادل، هویت درخواست را عوض نمی‌کند.

نام مطابق قرارداد هدف Backend، پس از Trim و یکسان‌سازی فاصله‌ها ۳ تا ۱۰۰ کاراکتر و دست‌کم سه حرف دارد؛ مجموعه نویسه‌های مجاز نیز مطابق همان DTO/Controller هدف است. ارقام فارسی و عربی، فاصله/پرانتز/خط تیره و پیش‌شماره‌های ایران نرمال می‌شوند. شماره نهایی باید `09` و ۱۱ رقم باشد.

دکمه در زمان ارسال و پس از موفقیت غیرفعال است. Timeout برابر ۲۰ ثانیه است. خطاهای شبکه، 400، 409، 429 و 503 پیام مشخص دارند. تنها پاسخ با `success === true` فرم را پاک می‌کند و موفقیت را اعلام می‌کند. Analytics موجود حفظ شده، نتیجه موفق فقط پس از تأیید Backend ثبت می‌شود و اطلاعات شخصی یا خدمت ساختگی به آن اضافه نشده است.

خطاها داخل خود فرم، با `aria-live` نمایش داده می‌شوند. در بررسی موبایل مشخص شد Toastهای خطای عمومی فعلی روی کنترل‌های فرم انباشته می‌شوند؛ برای همین فرم از نمایش تکراری Toast خطا استفاده نمی‌شود. Toast موفقیت موجود حفظ شده و کامپوننت عمومی Toast دست‌نخورده است.

## داشبوردها و موارد حفظ‌شده

Mapperهای موجود ادمین و مشاور رکوردهای دریافت‌شده را حفظ می‌کنند؛ مسیر دریافت لید تغییر نکرده است. تنها فیلدهای اختیاری `sourceType`/`SourceType` برای تایپ پاسخ، یک ستون منشأ در جدول ادمین و برچسب Website در سه محل نمایش لید مشاور اضافه شده‌اند. فیلتر، رزرو، تخصیص، تایمر و ساختار داشبورد بازنویسی نشده‌اند.

فایل TypeScript داشبورد مشاور، تنظیمات Angular و SSR، فایل‌های Environment، dependencyها و lockfile با `Clinic-APK` بدون تغییر باقی مانده‌اند. به `87c4825` بازگردانی انجام نشده است. مشکلات lockfile و فایل‌های JS دیده‌شده در بررسی اولیه `stage` مربوط به مقصد نهایی نبودند و منتقل نشدند. تعداد فایل‌های `.js` در `src` مقصد و خروجی تغییرات: **صفر**.

## CI و ادامه لازم برای پذیرش نهایی

Workflow دو نتیجه مستقل دارد: سلامت فرانت با HTTP fixture، و پیش‌نیاز قرارداد `codex-lflotm`. در اجرای اولیه endpoint هنوز روی برنچ عملیاتی نبود. پس از Merge بک‌اند، تکرار بررسی روشن کرد `rg` روی Runner نصب نیست؛ فرمان بررسی به `grep -Fq` استاندارد با همان متن دقیق DTO تغییر یافت. این تغییر صرفاً ابزار بررسی CI است و قرارداد یا کد برنامه را تغییر نمی‌دهد. بررسی پیش‌نیاز SQL E2E نیست.

برای تأیید کامل مسیر اجرایی، سناریوی واقعی Home → HTTP → LeadAssignments با SourceType=Website → چرخه تخصیص موجود → API مشاور باید در دیتابیس تست اجرا شود. تا آن زمان نتیجه این تست مشترک **باز** است. Deploy مجاز یا انجام نشده است.

Merge بک‌اند با تأیید کاربر انجام شده است؛ Merge فرانت نیز در همین مرحله از طرف کاربر تأیید شده است. هیچ Deploy یا تغییر روی دیتابیس عملیاتی انجام نشده است.
