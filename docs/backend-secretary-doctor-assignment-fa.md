# قرارداد بک‌اند — تخصیص دکتر به بیمار توسط منشی

این سند تغییرات موردنیاز API برای صفحه «تخصیص دکتر به بیمار» در پنل منشی را مشخص می‌کند. فرانت‌اند برای این قابلیت به سه عملیات زیر وابسته است.

## ۱. دریافت رزروها در بازه تاریخ

از Endpoint موجود رزروهای منشی استفاده می‌شود:

```http
GET /api/Reservation/SecretaryReservations
```

### Query Parameters مورد استفاده

| پارامتر | نوع | الزامی | توضیح |
| --- | --- | --- | --- |
| `fromDate` | `string` با قالب `YYYY-MM-DD` | بله | ابتدای بازه تاریخ رزرو، شامل همان روز |
| `toDate` | `string` با قالب `YYYY-MM-DD` | بله | انتهای بازه تاریخ رزرو، شامل همان روز |
| `includeCanceled` | `boolean` | بله | در این صفحه `false` ارسال می‌شود |
| `sortDirection` | `asc` یا `desc` | بله | در این صفحه `asc` ارسال می‌شود |
| `pageNumber` | `number` | بله | دریافت از صفحه `1` شروع و تا آخرین صفحه ادامه پیدا می‌کند |
| `pageSize` | `number` | بله | در این صفحه `100` ارسال می‌شود و فرانت همه صفحات را دریافت می‌کند |

`fromDate` و `toDate` باید بر مبنای تاریخ رزرو و با درنظرگرفتن منطقه زمانی ایران اعمال شوند. هر دو سر بازه inclusive هستند. پارامتر ساعت برای این قابلیت وجود ندارد.

هر آیتم پاسخ حداقل باید فیلدهای زیر را داشته باشد:

```json
{
  "id": 125,
  "patientName": "علی رضایی",
  "patientPhoneNumber": "09121234567"
}
```

ساختار صفحه‌بندی همان قرارداد فعلی `SecretaryReservations` باقی می‌ماند.

## ۲. دریافت جزئیات رزرو

```http
GET /api/Reservation/{reservationId}
```

### پاسخ موفق

پاسخ می‌تواند مستقیماً DTO یا داخل Envelope استاندارد `data` باشد و حداقل شامل موارد زیر است:

```json
{
  "isSuccess": true,
  "data": {
    "id": 125,
    "patientName": "علی رضایی",
    "patientPhoneNumber": "09121234567",
    "consultantFullName": "مریم احمدی",
    "reservationAt": "2026-08-25T09:30:00+03:30",
    "doctorName": "دکتر محمدی"
  }
}
```

رزرو فقط در صورتی برگردانده شود که منشی جاری مجوز مشاهده آن را داشته باشد.

## ۳. ثبت نام دکتر

```http
POST /api/Reservation/{reservationId}/assign-doctor
Content-Type: application/json
Authorization: Bearer <token>
```

### Body

```json
{
  "doctorName": "دکتر محمدی"
}
```

### قواعد اعتبارسنجی

- `doctorName` بعد از Trim نباید خالی باشد.
- طول و نویسه‌های مجاز نام باید مطابق قواعد عمومی متن در سامانه اعتبارسنجی شوند.
- شناسه منشی از JWT خوانده شود و از Body دریافت نشود.
- منشی باید مجوز مدیریت رزرو موردنظر را داشته باشد.
- ثبت مجدد برای همان رزرو، مقدار قبلی `doctorName` را جایگزین می‌کند.

### پاسخ موفق

```json
{
  "isSuccess": true,
  "message": "دکتر با موفقیت به بیمار تخصیص داده شد."
}
```

### پاسخ خطا

خطاها باید با Status Code مناسب (`400`، `401`، `403` یا `404`) و Envelope استاندارد پروژه برگردند تا پیام قابل نمایش به کاربر باشد.

## نکات امنیت و هم‌زمانی

- تمام Endpointها فقط برای نقش منشی و طبق سطح دسترسی رزرو قابل فراخوانی باشند.
- Backend نباید اطلاعات بیمار خارج از محدوده دسترسی منشی را برگرداند.
- برای جلوگیری از تغییر گمشده در درخواست‌های هم‌زمان، عملیات ثبت نام دکتر باید اتمیک باشد.
