# مستند فیلتر نوع ثبت‌کننده گزارش رزروهای روزانه ادمین

## هدف و جریان کاربری

در صفحه «رزروهای روزانه» ادمین، گزارش نمایشی و فایل خروجی باید همیشه از یک مجموعه فیلتر مشترک استفاده کنند:

1. ادمین تاریخ ثبت رزرو را انتخاب می‌کند.
2. از فیلد «نوع رزرو»، یکی از «رزروهای مشاوران» یا «رزروهای منشی‌ها» را انتخاب می‌کند.
3. فهرست دوم متناسب با نوع انتخابی تغییر می‌کند:
   - برای مشاوران: «همه مشاوران» و سپس فهرست مشاوران.
   - برای منشی‌ها: «همه منشی‌ها» و سپس فهرست منشی‌ها.
4. ادمین می‌تواند همه افراد آن گروه یا یک فرد مشخص را انتخاب کند.
5. دکمه «نمایش گزارش» همین فیلترها را روی کارت‌های خلاصه و جدول اعمال می‌کند.
6. دکمه «خروجی اکسل» دقیقاً همین فیلترها را به endpoint خروجی می‌فرستد.

با تغییر نوع رزرو، فرد انتخاب‌شده پاک می‌شود تا شناسه مشاور به اشتباه همراه فیلتر منشی (یا برعکس) ارسال نشود. فیلتر وضعیت همچنان قابل ترکیب با تاریخ، نوع رزرو و فرد است.

## منابع فهرست‌ها

### مشاوران

```http
GET /api/Consultant/GetConsultants?pageNumber=1&pageSize=500
Authorization: Bearer <token>
```

شناسه ارسالی برای هر مشاور، `profileId` است.

### منشی‌ها

```http
GET /api/admin/secretaries?pageNumber=1&pageSize=500
Authorization: Bearer <token>
```

شناسه ارسالی برای هر منشی، شناسه کاربری رشته‌ای `id` است. هر دو فهرست باید فقط برای ادمین مجاز باشند و بهتر است رکوردهای فعال را برگردانند.

## قرارداد API گزارش

هر دو endpoint زیر باید پارامترهای یکسانی را بپذیرند:

```http
GET /api/admin/reports/daily-reservations
GET /api/admin/reports/daily-reservations/export
```

| پارامتر | نوع | توضیح |
| --- | --- | --- |
| `date` | `string` | تاریخ ثبت رزرو با قالب `YYYY-MM-DD` و بر مبنای وقت ایران |
| `reservationOwnerType` | `Consultant \| Secretary` | گروه ثبت‌کننده رزرو |
| `consultantProfileId` | `number` | فقط در حالت `Consultant` و برای انتخاب یک مشاور |
| `secretaryUserId` | `string` | فقط در حالت `Secretary` و برای انتخاب یک منشی |
| `requestStatus` | `number` | فیلتر اختیاری وضعیت درخواست |
| `includeAll` | `boolean` | رفتار قدیمی نمایش همه رزروها بدون فیلتر |

### نمونه‌ها

همه رزروهای مشاوران در تاریخ انتخابی:

```http
GET /api/admin/reports/daily-reservations?date=2026-08-17&reservationOwnerType=Consultant
```

رزروهای یک مشاور در همان تاریخ:

```http
GET /api/admin/reports/daily-reservations?date=2026-08-17&reservationOwnerType=Consultant&consultantProfileId=42
```

همه رزروهای منشی‌ها در تاریخ انتخابی:

```http
GET /api/admin/reports/daily-reservations?date=2026-08-17&reservationOwnerType=Secretary
```

رزروهای یک منشی در همان تاریخ:

```http
GET /api/admin/reports/daily-reservations/export?date=2026-08-17&reservationOwnerType=Secretary&secretaryUserId=USER_ID
```

## قواعد بک‌اند

- `date` باید برای هر دو نوع رزرو روی **زمان ثبت رزرو** و با مرز روز در منطقه زمانی ایران اعمال شود.
- در حالت `Consultant`، رزروهایی برگردند که ثبت‌کننده/مالک آن‌ها مشاور است؛ نبود `consultantProfileId` به معنای همه مشاوران است.
- در حالت `Secretary`، رزروهایی برگردند که ثبت‌کننده/مالک آن‌ها منشی است؛ نبود `secretaryUserId` به معنای همه منشی‌ها است.
- شناسه نامرتبط با نوع انتخابی نادیده گرفته یا با پاسخ `400` رد شود؛ نباید باعث نشت نتیجه از گروه دیگر شود.
- منطق query، مرتب‌سازی و محاسبه `summary` میان endpoint نمایشی و endpoint خروجی مشترک باشد تا تعداد و رکوردها دقیقاً یکسان بمانند.
- در حالت `includeAll=true` همه فیلترهای دیگر نادیده گرفته شوند تا سازگاری قابلیت قبلی حفظ شود.
- ساختار `DailyReservationsReport` و ستون‌های فعلی خروجی بدون تغییر باقی بماند. در صورت نیاز برای شفافیت گزارش می‌توان ستون نام و نوع ثبت‌کننده را در بک‌اند به هر دو خروجی افزود.

## معیارهای پذیرش

1. انتخاب تاریخ و «همه مشاوران»، فقط رزروهای مشاوران همان تاریخ را در جدول، خلاصه و فایل خروجی نشان دهد.
2. انتخاب یک مشاور، نتیجه را به همان مشاور و تاریخ محدود کند.
3. انتخاب تاریخ و «همه منشی‌ها»، فقط رزروهای منشی‌ها همان تاریخ را برگرداند.
4. انتخاب یک منشی، نتیجه را به همان منشی و تاریخ محدود کند.
5. تغییر نوع رزرو، انتخاب فرد قبلی را پاک کند و فهرست مرتبط را نمایش دهد.
6. ترکیب فیلتر وضعیت با همه حالت‌های بالا یکسان در صفحه و خروجی اعمال شود.
7. خطای دریافت هر فهرست در رابط نمایش داده شود و دکمه تلاش مجدد وجود داشته باشد.
8. فعال‌کردن «نمایش همه رزروها» رفتار مستندشده `includeAll=true` را حفظ کند.
